# GitHub Issue 登録スキル

定められたフォーマットに従った GitHub Issue を作成・登録するスキルです。
**バリデーションスクリプトによるチェックを通過した Issue のみ登録**するため、誤ったフォーマットでの登録を防止します。

## ワークフロー

```
1. 種別を決定する
2. テンプレートから Issue ファイルを作成する
3. バリデーションを実行する（必須）
4. --dry-run でプレビューし、ユーザーに確認してもらう
5. 登録する
```

**バリデーション（Step 3）をスキップしたまま登録（Step 5）を実行してはいけません。**
登録スクリプトは内部でバリデーションを再実行し、エラーがあれば登録を拒否します。

---

## Issue フォーマット

Issue は **YAML フロントマター + Markdown 本文** の1ファイルで構成します。

```markdown
---
title: "[種別] 簡潔なタイトル"
labels:
  - <ラベル>
---

## 概要

（この Issue で行うことを簡潔に）

## タスク

- [ ] タスク1
```

### 種別とラベル

| 種別 | タイトル接頭辞 | ラベル | 必須セクション | 用途 |
|---|---|---|---|---|
| 企画 | `[企画]` | `article` | 概要・方針・タスク・完了条件 | 新規機能・記事・調査などの企画・立案 |
| 改善 | `[改善]` | `enhancement` | 概要・現状の課題・改善案・完了条件 | 既存コンテンツ・スキル・ガイドラインの改善 |
| バグ | `[バグ]` | `bug` | 概要・再現手順・期待する動作・実際の動作 | 不具合・エラーの報告 |
| タスク | `[タスク]` | `task` | 概要・タスク・完了条件 | その他の作業全般 |
| 質問 | `[質問]` | `question` | 概要・質問内容 | 質問・相談 |

### タイトルルール

- **形式**: `[種別] タイトル`（種別は上表の5種類のみ）
- **長さ**: 60文字以内（41文字以上は警告）
- **末尾**: 句点（。.）を付けない
- **1行のみ**（改行を含めない）
- プレースホルダー（`{{...}}`）を残さない

### 本文ルール

- **必須セクション**: 種別ごとに上表で定めた `## セクション` をすべて含める
- **見出しレベル**: `##`（H2）のみ使用。H1（`# `）はタイトルフィールドで指定するため本文では禁止
- **チェックリスト**: `企画`・`タスク` は `- [ ]` のチェックリストを1項目以上含める
- **プレースホルダー**: `{{...}}` を本文に残さない
- **分量**: 本文は最低100文字以上（情報不足のIssueを防ぐ）

### ラベルルール

- 種別に対応するラベル（上表）を必ず1つ以上含める
- 使用可能なラベルは `article` / `enhancement` / `bug` / `task` / `question` のみ
- タイトルの種別とラベルは一致させる（例: `[バグ]` なら `bug` を必ず含める）

### 禁止事項

| 禁止項目 | 理由 |
|---|---|
| 種別不明・未定義種別（`[要望]` など） | フォーマットを固定するため |
| 本文中の H1 見出し（`# `） | タイトルは frontmatter で指定するため |
| `{{...}}` プレースホルダーの残存 | 未記入項目を防ぐため |
| タイトル末尾の句点 | タイトル表記の統一のため |
| 不明なフロントマターキー | フォーマットの拡散を防ぐため |

## テンプレート

種別ごとのテンプレートを用意しています。必ずテンプレートから作成します。

| 種別 | テンプレート |
|---|---|
| 企画 | `assets/article.md` |
| 改善 | `assets/enhancement.md` |
| バグ | `assets/bug.md` |
| タスク | `assets/task.md` |
| 質問 | `assets/question.md` |

---

## 手順

### Step 1: 種別を決定する

ユーザーの依頼内容から最も適した種別を上表から選択します。

- 新規機能・記事・調査などの企画 → `企画`
- 改善提案 → `改善`
- 不具合報告 → `バグ`
- その他の作業 → `タスク`
- 質問・相談 → `質問`

### Step 2: テンプレートから Issue ファイルを作成する

`tmp/` 配下に Issue ファイルを作成します。

```bash
# テンプレートをコピー（プラグインのスキルディレクトリから）
SKILL_DIR=$(dirname "$(dirname "${BASH_SOURCE[0]}")")  # このスキルが配置されるディレクトリ
cp "$SKILL_DIR/assets/<種別>.md" tmp/issue-<種別>.md

# 内容を編集
```

> スキルディレクトリの実際のパスは環境により異なります。`<種別>` は `article` / `enhancement` / `bug` / `task` / `question` のいずれかです。

**作成時の注意**:
- タイトルは `[種別] 簡潔なタイトル` 形式（60文字以内、末尾に句点なし）
- プレースホルダー（`{{...}}`）をすべて実際の内容に置き換える
- 必須セクションは削除しない（不要な場合は「なし」と明記する）

### Step 3: バリデーションを実行する（必須）

```bash
bash "$SKILL_DIR/scripts/validate-issue.sh" tmp/issue-<種別>.md
```

- **エラーが0件になるまで修正を繰り返す**
- エラーがある場合は登録してはいけない
- 警告（⚠）は修正を推奨（エラーではないので登録は可能）

### Step 4: プレビューしてユーザーに確認してもらう

登録前に `--dry-run` でプレビューを実行し、内容をユーザーに提示して確認を得ます。

```bash
bash "$SKILL_DIR/scripts/create-issue.sh" tmp/issue-<種別>.md --dry-run
```

`--dry-run` は以下を実行します。

1. バリデーションを実行（エラーがあれば**ここで終了**）
2. タイトル・ラベル・本文を表示
3. **Issue は登録しない**（プレビューのみ）

表示された内容（タイトル・ラベル・本文）に問題がないかユーザーに確認します。

### Step 5: 登録する

```bash
bash "$SKILL_DIR/scripts/create-issue.sh" tmp/issue-<種別>.md
```

登録スクリプトは以下を実行します。

1. バリデーションを再実行（エラーがあれば**登録を拒否**）
2. `gh` CLI のインストール・認証を確認
3. **ラベルの存在確認**（存在しないラベルは自動的に作成）
4. タイトル・ラベル・本文を抽出して `gh issue create` で登録

**前提条件**: GitHub CLI（`gh`）がインストールされ、ログイン済みであること

```bash
# 未導入の場合
gh auth login
```

**ラベルの自動作成**: `article` / `enhancement` / `bug` / `task` / `question` のうち、リポジトリに存在しないラベルは登録時に自動で作成されます（色・説明はスキル定義のもの）。

### 登録後の確認

- `gh issue list` で登録された Issue を確認します。
- 登録が完了したら `tmp/` の Issue ファイルは削除して構いません。

---

## When to Use

- GitHub に Issue を登録するとき
- 開発・執筆・改善・不具合などのタスクを Issue として管理したいとき
- 定められたフォーマットで Issue を登録したいとき
